1. Mission Overview

This project combines two subsystems into a single end-to-end autonomous spacecraft docking simulation:

  • Phase 1 (Orbital GNC) — Classical guidance, navigation & control algorithms bring a chaser vehicle from a 400 km circular LEO to the ISS orbit at 35 786 km, then close the relative range from several kilometres down to ~491 m using Hohmann transfer, Lambert arc, Extended Kalman Filter, and PID attitude control.
  • Phase 2 (ML Vision) — A fine-tuned ResNet50 regression model processes sequential docking-approach images (512×512 px) to predict the pixel coordinates of the docking port and the range to it. A PD Proximity Controller converts the pixel prediction error into attitude correction torques for the final 491 m → 61 m approach.

Key Design Choice: The two phases share a single time axis. Phase 1 EKF is truncated at the exact time-step it first reaches 491 m, ensuring a continuous distance timeline with no backward jump.

3. Phase 1 — Orbital GNC

Phase 1 implements four classical spacecraft GNC steps, compacted from the original MiniProject.py into integrated_mission.py.

3.1 Step 1 — Hohmann Transfer

A Hohmann transfer uses two impulsive burns to move the chaser from an initial circular orbit ($r_1$) to the ISS orbit ($r_2$).

flowchart LR IN["Inputs\nalt_initial = 400 km\nalt_final = 35 786 km"]:::inp subgraph CALC["compute_hohmann()"] R["r₁ = alt₁ + R_Earth\nr₂ = alt₂ + R_Earth"] A["a_trans = (r₁+r₂)/2\ne_trans = (r₂−r₁)/(r₂+r₁)"] V["v₁ = √(μ/r₁) v₂ = √(μ/r₂)\nv_peri = √(2μ/r₁ − μ/a)\nv_apo = √(2μ/r₂ − μ/a)"] DV["ΔV₁ = v_peri − v₁\nΔV₂ = v₂ − v_apo\nΔV_total = |ΔV₁|+|ΔV₂|"] TOF["TOF = π √(a³/μ)"] R --> A --> V --> DV --> TOF end OUT["Outputs\nΔV_total ≈ 3.854 km/s\nTOF ≈ 317.5 min\na_trans, e_trans"]:::out IN --> CALC --> OUT classDef inp fill:#0f2f1e,stroke:#2ea043,color:#56d364 classDef out fill:#1e3a5f,stroke:#388bfd,color:#58a6ff

Figure 2 — Hohmann Transfer computation flow.

$$\Delta V_1 = \sqrt{\frac{2\mu}{r_1} - \frac{\mu}{a_t}} - \sqrt{\frac{\mu}{r_1}}, \qquad \Delta V_2 = \sqrt{\frac{\mu}{r_2}} - \sqrt{\frac{2\mu}{r_2} - \frac{\mu}{a_t}}$$ $$a_t = \frac{r_1 + r_2}{2}, \qquad T_{transfer} = \pi\sqrt{\frac{a_t^3}{\mu}}$$

3.2 Step 2 — Lambert Rendezvous

Lambert's problem: compute the impulsive velocity vectors $\mathbf{v}_0$ and $\mathbf{v}_f$ needed to travel from $\mathbf{r}_0$ to $\mathbf{r}_f$ in a prescribed time-of-flight. The solver uses Battin's universal variable formulation with Stumpff functions.

flowchart TD subgraph STUMPFF["Stumpff Helper Functions"] CS["C(z), S(z)\nHandles elliptic (z>0),\nhyperbolic (z<0),\nparabolic (z=0) cases"] end subgraph SCAN["lambert_uv() — z-scan + bisection"] SC["Scan z ∈ [−4π², 4π²]\n2000 sample points"] VALID["Filter valid z\n(y > 0 required)"] SIGN["Find sign-change bracket\n[z_lo, z_hi] where dt(z)=TOF"] BIS["Bisection root-find\n300 iterations, tol=1e-10"] YZ["Compute y from z\ny = r₀+r + A(zS−1)/√C"] VEC["v₀ = (r−f·r₀)/g\nvf = (ġ·r−r₀)/g"] SC --> VALID --> SIGN --> BIS --> YZ --> VEC end subgraph MINEN["lambert_min_energy()"] ME["Compute min-energy TOF\nvia parabolic arc geometry\nUsed as default TOF input"] end IN2["r_chaser, r_target\n(at ISS orbit, 7° apart)"]:::inp OUT2["v₀_lambert, vf_lambert\n(burn velocity vectors)"]:::out IN2 --> MINEN --> SCAN SCAN --> OUT2 STUMPFF --> SCAN classDef inp fill:#0f2f1e,stroke:#2ea043,color:#56d364 classDef out fill:#1e3a5f,stroke:#388bfd,color:#58a6ff

Figure 3 — Lambert rendezvous solver using universal variables and Stumpff functions.

$$y = r_0 + r + A\frac{zS(z)-1}{\sqrt{C(z)}}, \qquad A = t_m\sqrt{r_0 \cdot r \cdot (1+\cos\Delta\nu)}$$ $$\mathbf{v}_0 = \frac{\mathbf{r}_f - f\,\mathbf{r}_0}{g}, \qquad \mathbf{v}_f = \frac{\dot{g}\,\mathbf{r}_f - \mathbf{r}_0}{g}$$

3.3 Step 3 — EKF Navigation

A 12-state Extended Kalman Filter estimates the relative position, velocity, and attitude between the chaser and ISS docking port. The dynamics follow the Clohessy–Wiltshire (CW) linearised relative motion equations. Laser ranging provides range ($\rho$), elevation ($\alpha$), and azimuth ($\beta$) measurements at 1 Hz.

flowchart LR subgraph STATE["12-State Vector X"] XS["pos_rel [0:3] (x, y, z) km\nvel_rel [3:6] (ẋ, ẏ, ż) km/s\nquaternion [6:10] (q₀,q₁,q₂,q₃)\nangular rate [10:12] (ωx,ωy) rad/s"] end subgraph PRED["Predict Step — ekf_predict_step()"] CW["CW State Transition Φ\ncw_stm(dt, n=Ω_orbit)"] QI["Quaternion Integration\nΩ matrix × q, renormalize"] XP["X⁻ = Φ X\nP⁻ = Φ P Φᵀ + Q"] CW --> QI --> XP end subgraph MEAS["Measurement — h_las(X)"] HL["ρ = √(x²+y²+z²)\nα = arcsin(−z/ρ)\nβ = arctan2(y, x)"] end subgraph UPD["Update Step — ekf_update_step()"] JAC["H Jacobian\n∂h/∂X (3×12)"] KG["S = H P⁻ Hᵀ + R\nK = P⁻ Hᵀ S⁻¹"] INN["Innovation ν = z_meas − h(X⁻)\n(angle wrap-around)"] JOS["Joseph-form covariance\nP = (I−KH) P⁻ (I−KH)ᵀ + K R Kᵀ"] JAC --> KG --> INN --> JOS end OUT3["Output per step\ndist = ‖X[0:3]‖ km\ntr(P) covariance trace"]:::out STATE -->|"initial X₀, P₀"| PRED PRED --> MEAS MEAS --> UPD UPD -->|"600 steps @ 1 Hz"| OUT3 UPD -->|"loop"| PRED classDef out fill:#1e3a5f,stroke:#388bfd,color:#58a6ff

Figure 4 — 12-state EKF navigation loop with CW dynamics and laser ranging.

$$\mathbf{X}^- = \Phi\,\mathbf{X}, \quad \mathbf{P}^- = \Phi\mathbf{P}\Phi^\top + \mathbf{Q}$$ $$\mathbf{K} = \mathbf{P}^-\mathbf{H}^\top(\mathbf{H}\mathbf{P}^-\mathbf{H}^\top + \mathbf{R})^{-1}$$ $$\mathbf{X}^+ = \mathbf{X}^- + \mathbf{K}(\mathbf{z} - h(\mathbf{X}^-))$$

3.4 Step 4 — PID Attitude Control

A PD controller drives the chaser's attitude quaternion from an initial orientation $q_0$ to a target docking attitude $q_t$ using Euler's rigid-body torque equations.

flowchart TD subgraph LOOP["run_pid_sim() — dt = 0.01 s"] QE["Quaternion error\ne_q = q_t ⊗ q_c⁻¹\nError vector e = 2 q_e[1:4]"] CTRL2["PD Control Law\nτ = clip( Kp·e − Kd·ω, ±τ_max )"] EULER["Euler Rigid-body Dynamics\nω̇ = J⁻¹(τ − ω × J·ω)\nω = clip(ω + ω̇·dt, ±ω_max)"] INT["RK4 Quaternion Integration\nq̇ = ½ q ⊗ [0, ω]\nrenormalize q"] CONV{"‖e‖ < 1e-3 and\n‖ω‖ < 1e-4 ?"} QE --> CTRL2 --> EULER --> INT --> CONV CONV -- "No → continue" --> QE end PARAMS["Parameters\nKp = 0.08 Kd = 0.8\nJ = diag(0.01, 0.015, 0.02) kg·m²\nτ_max = 0.5 N·m ω_max = 5 rad/s"]:::param OUT4["Outputs\n(t_log, e_log, torq_log)\nConvergence ~135 s"]:::out PARAMS --> LOOP --> OUT4 classDef param fill:#2d2208,stroke:#9e6a03,color:#f0c04d classDef out fill:#1e3a5f,stroke:#388bfd,color:#58a6ff

Figure 5 — PID attitude control loop with quaternion error and RK4 integration.

$$\boldsymbol{\tau} = \text{clip}\!\left(K_p\,\mathbf{e} - K_d\,\boldsymbol{\omega},\ \pm\tau_{\max}\right)$$ $$\dot{\boldsymbol{\omega}} = \mathbf{J}^{-1}(\boldsymbol{\tau} - \boldsymbol{\omega}\times\mathbf{J}\boldsymbol{\omega}), \quad \dot{\mathbf{q}} = \tfrac{1}{2}\,\mathbf{q}\otimes\begin{bmatrix}0 \\ \boldsymbol{\omega}\end{bmatrix}$$

4. Phase Handoff Logic

The transition from Phase 1 (EKF) to Phase 2 (ML) must be seamless on the distance-vs-time plot. The EKF simulation runs for 600 steps at 1 Hz. As the CW trajectory decays the relative range, the handoff occurs at the first step where dist ≤ 491 m.

flowchart LR EKF_SIM["run_ekf_sim(600 steps)\nOutputs: ekf_dist[0..599] in km"] CONV_M["Convert to metres\nekf_m = ekf_dist × 1000"] FIND["Find handoff index\nbelow = where(ekf_m ≤ 491)\nhandoff_idx = below[0]"] T_HO["t_handoff = handoff_idx × 1.0 s"] PLOT1["Plot EKF phase\n t ∈ [0, t_handoff]"] PLOT2["Plot ML phase\ntime axis starts at t_handoff\nML steps spaced 30 s each"] SHOW["Continuous plot\nno backward distance jump"]:::out EKF_SIM --> CONV_M --> FIND --> T_HO T_HO --> PLOT1 T_HO --> PLOT2 PLOT1 --> SHOW PLOT2 --> SHOW classDef out fill:#166534,stroke:#22c55e,color:#fff

Figure 6 — Phase handoff: EKF truncated at 491 m; ML timeline starts at the same moment.

Bug that was fixed: Without truncation, the EKF distance decayed to ~249 m over 600 steps, then the ML phase re-started at 491 m — creating a 242 m backward jump in the timeline. The fix truncates the EKF plot at the first sub-491 m sample, then attaches the ML phase at that exact time.

5.2 ResNet50 Inference Pipeline

The model is a transfer-learning architecture: a frozen ResNet50 encoder (ImageNet weights) with a regression head trained to predict three normalised output values that are then denormalised using dataset-level min-max statistics.

5.3 Proximity Controller (PD)

The ProximityController class converts the predicted pixel position of the docking port into angular attitude correction torques using a PD law.

flowchart TD subgraph CONV["Pixel → Angle conversion"] PIX["Pixel errors\nΔx_px = x_pred − 256\nΔy_px = y_pred − 256\n(image centre = 256,256)"] ANG["Angular errors\nε_az = Δx_px × (FOV/pixel)\nε_el = Δy_px × (FOV/pixel)\nFOV/pixel = 40°/512 = 0.0781°/px"] PIX --> ANG end subgraph PD["PD Control Law"] DERIV["Derivative\nε̇_az = (ε_az − ε_az_prev) / dt\nε̇_el = (ε_el − ε_el_prev) / dt"] TQ["Torques\nτ_az = −(Kp·ε_az + Kd·ε̇_az)\nτ_el = −(Kp·ε_el + Kd·ε̇_el)\nKp=2.5×10⁻³ Kd=8.0×10⁻³"] CLIP["Clip to ±0.05\n(normalised torque units)"] DERIV --> TQ --> CLIP end subgraph LOG2["History Logging"] REC["Per-step record\n{step, dist_m, az_err_deg, el_err_deg,\ntotal_err (deg), az_torque, el_torque}"] end PRED2["(x_pred, y_pred, dist_m)\nfrom model inference"]:::inp OUT5["(az_torque, el_torque)\nAttitude correction commands"]:::out PRED2 --> CONV --> PD --> LOG2 CLIP --> OUT5 classDef inp fill:#0f2f1e,stroke:#2ea043,color:#56d364 classDef out fill:#1e3a5f,stroke:#388bfd,color:#58a6ff

Figure 9 — Proximity controller: pixel error to angular torque via PD law.

$$\varepsilon_{az} = (x_{pred} - x_c)\cdot\frac{FOV_{rad}}{N_{px}}, \qquad \varepsilon_{el} = (y_{pred} - y_c)\cdot\frac{FOV_{rad}}{N_{px}}$$ $$\tau_{az} = -\left(K_p\,\varepsilon_{az} + K_d\,\dot{\varepsilon}_{az}\right), \qquad \tau_{el} = -\left(K_p\,\varepsilon_{el} + K_d\,\dot{\varepsilon}_{el}\right)$$ $$\text{LoS Error} = \sqrt{\varepsilon_{az}^2 + \varepsilon_{el}^2} \quad [\text{degrees}]$$

9. Code Structure

All integration code lives in integrated_mission.py, organised into 10 clearly separated sections.

  • Section 1 — Dataset Loader

    load_dataset_csv() — reads data/train.csv using only stdlib csv.DictReader, no pandas.
    find_image_for_distance() — argmin distance lookup.
    build_scaler_from_data() — computes (x_min, x_max, y_min, y_max, d_min, d_max).
    denorm_simple() — min-max inverse transform.

  • Section 2 — Model Loader + Inference

    load_model_tf() — wraps tf.keras.models.load_model, returns None if TF unavailable.
    preprocess_for_model() — BGR→RGB, resize to 224×224, ImageNet normalisation.
    run_inference() — runs model or CSV fallback.

  • Section 3 — Proximity Controller

    ProximityController class — PD controller converting pixel offset to angular attitude torques, with per-step history logging.

  • Section 4 — Orbital Mechanics (Phase 1)

    Compacted from MiniProject.py:
    compute_hohmann(), kepler_position(), Stumpff functions _C()/_S(), lambert_uv(), lambert_min_energy(), propagate_twobody(), cw_stm(), ekf_predict_step(), h_las(), H_jac(), ekf_update_step(), run_ekf_sim(), run_pid_sim().

  • Section 5 — ML-Guided Close Approach

    run_ml_phase() — the 12-step inference + control loop. Returns (steps_data, ctrl_hist).

  • Section 6 — Image Strip Visualisation

    save_image_strip() — annotated 2×6 grid of approach imagery.

  • Section 7 — Master Dashboard

    save_mission_dashboard() — 9-panel dark-theme dashboard with gridspec layout (20×15 in, 150 dpi).
